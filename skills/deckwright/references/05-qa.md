# The QA loop

What is run on a deck before anyone else sees it, and what each thing can and
cannot prove. Everything here is wired into `scripts/gate.ps1`, which is the
single entry point: `powershell -NoProfile -File scripts/gate.ps1`.

## Three kinds of check, kept distinct

They fail for different reasons and a green one says nothing about the
others.

| Kind | Question | Tool |
|---|---|---|
| File integrity | does the package open, twice, without PowerPoint repairing it | `scripts/check_pptx.ps1` |
| Visual composition | is the same region in the same place on every slide | `scripts/export_png.ps1` then `scripts/compose_qa.py` |
| Content lint | does the text say what the spec said, and nothing it must not | `scripts/lint_deck.py` |

A deck whose spec says `Output: html` has no package to open, so the first
row does not apply to it and the other two do - on the drafts rather than on
a `.pptx`. [The HTML deck](#the-html-deck) says how.

A deck can open perfectly and carry an internal tracking code on slide 9. A
deck can lint clean and have its footer five pixels low on one slide out of
thirty. A deck can look right in every PNG and be a package PowerPoint
repairs on the client's machine.

There is a fourth habit that is not a check: **dump the text and diff it
before regenerating anything.** That is catalogue item 22 in
`references/06-gotchas.md`, and it is the only thing standing between a
rebuild and the author's manual edits. See
[Text dump and diff](#text-dump-and-diff).

## File integrity through COM

```
powershell -NoProfile -File scripts/check_pptx.ps1 -Path out/walk/deck.pptx
```

Opens the file through PowerPoint COM **twice in the same run**, and fails
outright if `Open()` throws on either pass. Opening once proves little: some
corruption classes are tolerated and silently fixed on a file's first open
and only manifest on a later one - catalogue item 19.

Each pass prints one line:

```
pass 1: OPEN_OK slides=2 hidden=
pass 2: OPEN_OK slides=2 hidden=
CHECK PASSED
```

The `hidden=` field lists the 1-based positions whose
`SlideShowTransition.Hidden` is set - COM's own view of the hidden flag,
which is a useful second opinion against what the package's XML says
(catalogue item 7). An empty field means no slide is hidden.

**`-Save` forces the presentation dirty before saving, and fails if it could
not.** On pass 1 only, the file is opened writable, `$pr.Saved` is set to
`$false` (with an add-a-shape-then-delete-it fallback if that property turns
out read-only on some build), the script fails outright if `Saved` did not
actually change, and only then calls `.Save()`. This is not ceremony.
`Presentation.Save()` on a freshly-opened, unmodified presentation is a
documented no-op - `.Saved` is already true, nothing is written, and the
bytes on disk come back identical. An earlier version of this switch called
`.Save()` straight after `Open()` and reported success against exactly that
no-op, which is how a false "embedded fonts survive a PowerPoint save"
ruling reached `docs/decisions.md` before a review round reversed it. The
corrected ruling, and the measurement that reversed it, are in
`docs/decisions.md`.

**What the doubled open does not detect: a silent in-place repair.** With
`WithWindow = $false` there is no interactive repair prompt for the script to
observe, and pass 2 opens read-only specifically so a corrected copy is never
written back. A package PowerPoint repairs in place - no throw, no prompt,
just different bytes than were asked for - passes both passes exactly like a
healthy file. `references/06-gotchas.md#19` says so in the catalogue; nothing
in this repository pins that case.

Windows with PowerPoint only. There is no substitute.

## PNG export

```
powershell -NoProfile -File scripts/export_png.ps1 -Path out/walk/deck.pptx -Out out/png_walk -Expect 2
```

Writes one `sNN.png` per slide at 1600x900 into `-Out`, which is **deleted
and recreated first**: without that, a broken export leaves the previous
run's images in place and looks exactly like a successful one. `-Expect` is
the number of slides that must come out, and the script also fails if the
count of PNGs written does not equal the slide count, or if nothing was
exported at all.

Export is per slide (`Slides.Item($i).Export`), so **hidden slides are
rendered too** and `-Expect` counts them. That is the opposite of a slide
show, and it is what makes the hidden slides reviewable at all.

The PNGs are the input to composition, and they are the artifacts a review
cites: a finding names the PNG and the shape id, never the report.

## Visual QA by composition

An agent that cannot look at a deck can still do pixel work by comparing one
region across every slide. A footer five pixels low on slide 17 is invisible
slide by slide and obvious in a stack.

`scripts/compose_qa.py` has three subcommands.

```
python scripts/compose_qa.py band --png-dir out/png_walk --box 0,836,1600,900 --expect 2 --out out/qa/band.png
python scripts/compose_qa.py zoom --png-dir out/png_walk --slides 1,2 --box 1400,840,1600,900 --scale 2 --out out/qa/zoom.png
python scripts/compose_qa.py ink  --image out/qa/band.png --rows 2 --gutter 200 --blank 1 --inked 2
```

**`band`** crops the same strip from every slide and stacks the crops, one
per row, with a 200-pixel labelled gutter down the left. **`zoom`** does the
same for chosen slides at `--scale` (nearest-neighbour, so a one-pixel offset
stays one pixel rather than blurring into a gradient), with a 130-pixel
gutter. The row separator is drawn **inside the gutter only** - a rule across
the crop would overwrite its bottom pixel row, which for a footer band is
exactly the row that matters.

**The exact-count rule.** `--expect N` fails unless exactly N slide PNGs were
found, and an empty set always fails. A glob that matched four of seven PNGs
would otherwise compose four rows that nobody counts. `find_slides` also
names a missing number instead of skipping it, so `--slides 1,2` on a
directory with no `s02.png` raises rather than composing one row.

**The box is validated against every image.** Pillow pads an out-of-range
crop with black instead of raising, so a strip composed entirely of padding
would look uniformly clean. `_crop` refuses any box not fully inside the
image and names the file and its size.

**1600x900 versus 1280x720: the factor is 1.25.** Builders place shapes on
the 1280x720 design canvas; the PNGs come out at 1600x900. Multiply design
coordinates by `1600 / 1280 = 1.25` to get a crop box. The gate's own boxes
are the worked example. The example brand puts its copyright line at design
`y = 690`, 14 px tall, and its page marker at design `x = 1172, y = 690,
60 x 14`:

| Thing | Design | x 1.25 | Gate's box |
|---|---|---|---|
| copyright line | y 690..704 | y 862.5..880 | band `0,836,1600,900` |
| page marker | x 1172..1232, y 690..704 | x 1465..1540, y 862.5..880 | zoom `1400,840,1600,900` |

Both boxes sit comfortably around their target with margin for the descender
and for a shape that drifted; neither is tight enough that a correct deck
fails.

**`ink` asserts content per row, and that is why the gate uses it.** It
counts, for each row of a composed strip, the pixels right of the gutter that
differ from their own scanline's first pixel, then raises if a row named in
`--inked` has none or a row named in `--blank` has any. Row numbers outside
`1..rows` are refused before anything is counted, so `--blank 4` on a
two-row image cannot pass vacuously.

The gate asserts this rather than the composite's *size* because a band's
size is `gutter + box width` by `box height x slides` **by construction** - it
follows from the arguments, and a size assertion therefore cannot fail on
anything about the deck. That is the inert-meta-check shape a Phase 2 review
caught once already. A crop box that drifted off the footer composes a clean
strip of exactly the right size; only its content says so.

Pinned by `tests/test_compose_qa.py` and by four gate steps: `compose band`,
`compose zoom`, `band shows the footer`, `zoom shows the page marker`. The
`compose zoom` step deliberately carries no `--expect`: with `--slides 1,2`
explicit, `find_slides` raises on a missing member before the count check
runs, so the flag could never fail on anything (`docs/decisions.md`).

Needs Python and `Pillow` only - but its input is the COM export, so in
practice it needs Windows upstream.

## Content lint

```
python scripts/lint_deck.py --deck out/walk/deck.pptx --rules examples/walkthrough/lint.toml --expect-checks 8
python scripts/lint_deck.py --deck examples/ai-horizon/drafts --rules examples/ai-horizon/lint.toml --expect-checks 7
python scripts/lint_deck.py --brand relay
```

Reads the text of a built deck and its notes, and applies eight checks driven
entirely by a TOML rules file. Text is harvested through
`textedit.iter_paragraphs`, which recurses into groups and table cells - a
shallow harvester misses grouped text, which is where a forbidden token
hides.

**`--deck` takes a directory of drafts as well as a `.pptx`**, and the same
rules file governs both: the content constraints belong to the deck, not to
the file format it ships as. See [the HTML deck](#the-html-deck).

**`--brand NAME` with no `--deck` runs the `[assets]` check alone.** That
check never reads the deck - it walks the brand directory against its
`assets.toml` - and "Set up a brand" step 4 asks for it two stages before a
deck or a rules file exists. Requiring both was why the manifest could only
be verified by building a deck first. Pinned by
`tests/test_lint_deck.py::test_the_assets_check_runs_against_a_brand_with_no_deck`.

The rules file, every table annotated:

```toml
# Each table names one check. A table that is absent, or present with an
# empty list, makes its check SKIPPED - never passed.

[typos]
# Literal needles. Matched against the slide's whitespace-flattened text,
# so a needle split across a line break is still found.
needles = ["ASSESSEMENT", "recieve", "seperate"]

[codes]
# Regexes for internal tracking codes that must never reach the client.
# Each distinct hit is reported once per slide, sorted.
patterns = ['\bD[123]-\d{2}\b', '\bDA-\d{2}\b']

[forbidden]
# Literal tokens, matched case-insensitively: vendor names, employer names,
# a codename that was fine internally. `tokens_file` is a path - relative to
# THIS rules file, or absolute - to a newline-delimited list kept somewhere
# the deck directory does not have to carry. See "what [forbidden] cannot
# carry" below.
tokens = ["Some Vendor", "Project Bluebird"]
tokens_file = "~/deck-forbidden.txt"       # optional

[required]
# Boilerplate that must appear on every content slide.
# `exempt` lists file positions that legitimately lack it - the cover.
strings = ["(c) Example Organisation"]
exempt = [1]

[kickers]
# Exactly one section kicker per content slide, and only from `allowed`.
# `pattern` is matched against the NEWLINE-JOINED text, not the flattened
# text: kickers are paragraph-level and the pattern relies on the line
# boundary. A slide with none reports "no kicker"; a slide with two reports
# one finding naming both, plus one more for each kicker not in `allowed`.
# The character class names its accented capitals, and must: `[A-Z]` stops
# at the first one. See "The kicker pattern is a language decision" below.
pattern = '\b0[1-9]\. [A-ZÁÉÍÓÚÜÑ][A-ZÁÉÍÓÚÜÑ .&]{2,60}'
allowed = ["01. THE LOOP"]
exempt = [1]

[notes_only]
# Strings that must be in the speaker notes and on no slide. Reported twice
# over: once per slide that carries one, and once for the deck if it is in
# no note at all.
strings = ["If asked"]

[exact]
# Verified figures. `strings` are literal; `spec` is a path, relative to
# THIS rules file, to a spec whose "Exact string" column is read.
# See references/01-spec-stage.md#exact-figures-are-checked-not-trusted.
spec = "spec.md"

[assets]
# The brand package whose non-text files must all be accounted for.
brand = "relay"
```

**Output format.** One line per check, then one line per finding, then a
verdict:

```
check typos: rules=3 findings=0
check codes: rules=2 findings=1
FAIL codes slide=2: D1-04
check kickers: skipped (no rules)
LINT FAILED findings=1 ran=7 skipped=1
```

A finding's location is `slide=N` or, for a deck-level finding, `deck`.
Three checks produce deck-level findings: `notes_only`, for a string that is
in no note at all; `exact`, for a figure found verbatim on no slide; and
`assets`, for every one of its findings. Everything else names its slide,
`required` included - missing boilerplate is reported once per non-exempt
slide, never once for the deck.

A clean run prints `LINT PASSED ran=8 skipped=0`. Any finding exits 1; so
does a `--expect-checks` mismatch, which prints its own
`FAIL: expected N check(s) to run, ran=N skipped=N` first.

**The kicker pattern is a language decision, and it fails in the direction
that looks like the slide's fault.** `[A-Z]` is ASCII, so on a Spanish deck
`01. DÓNDE ESTÁ LA PRESIÓN` matches nothing at all - the class stops at the
`Ó`, the `{2,60}` minimum is never reached - and the tool reports
`no kicker` for a slide that visibly carries one. Worse, `03. DISEÑO Y
OPERACIÓN` matches the prefix `03. DISE` and reports a kicker that does not
exist, which invites adding `"03. DISE"` to `allowed` and makes the check
permanently wrong. The shipped pattern therefore names its accented
capitals, `[A-ZÁÉÍÓÚÜÑ]`, and a deck in another language extends the class
rather than the allowlist. **A slide reported as "no kicker" when it plainly
has one is a report about the pattern, not about the slide.** Pinned by
`tests/test_lint_deck.py::test_an_accented_kicker_is_found_whole_and_allowed`
and `tests/test_lint_deck.py::test_the_shipped_kicker_pattern_accepts_accented_capitals`.

**Every bad input comes out as one `FAIL: ...` line and exit 1, never a
traceback.** `main` catches `ValueError` (a scalar where a rule list belongs,
a list where a scalar belongs, a rules table that is not a table, an invalid
regex - named with its pattern, a spec with no `Exact string` column, a
malformed or duplicated manifest entry), `FileNotFoundError` and `OSError`
(a missing or unreadable rules file), `PackageNotFoundError` (python-pptx's
own, for a `--deck` that is missing or is not a readable package; it does not
derive from `OSError`, so it has to be named explicitly), and
`tomllib.TOMLDecodeError` (malformed rules TOML). Pinned by
`tests/test_lint_deck.py::test_the_cli_fails_cleanly_on_a_missing_rules_file`,
`tests/test_lint_deck.py::test_the_cli_fails_cleanly_on_a_missing_deck` and
`tests/test_lint_deck.py::test_the_cli_fails_cleanly_on_an_invalid_regex`.

**What `[forbidden]` cannot carry: the client's own name.** The rules file
sits in the deck directory and travels with the deck, so listing a client's
name there writes it into the one file it must not be in - and the check
that exists to keep a client name off the slides can then enforce only the
vendor half of the constraint. `tokens_file` is the way out: a path,
relative to the rules file or absolute (with `~` expanded), to a
newline-delimited list kept in a home directory or supplied by the
environment; blank lines and `#` comments are ignored, and the tokens count
towards the reported rule count exactly like inline ones. What it does not
solve is the report - a finding prints `FAIL forbidden slide=2: <token>` on
stdout, so redirecting a lint run into a committed log puts the name back.
Pinned by
`tests/test_lint_deck.py::test_forbidden_reads_tokens_from_a_file_outside_the_deck`.

**`[notes_only]` only makes sense when the deck carries notes.** Its
deck-level finding, `<string>: not in any note`, is exactly what a deck built
with `--notes none` produces for every string in the table, because there is
no note for the string to be in. For such a deck leave the `[notes_only]`
table out of the rules file and lower `--expect-checks` to 7; the two example
decks keep it because the gate builds them with `--notes both`. Catalogue
item 23 in `references/06-gotchas.md`.

**Skipped is not passed.** A check whose table is absent or empty prints
`skipped (no rules)` and is excluded from the `ran=` count. This matters
because a `needles = []` left behind by a careless edit turns the typo check
off while the gate stays green. `--expect-checks 8` is what closes that: the
gate asserts the exact number of checks that ran with at least one rule.

A check is also skipped when the deck under test cannot carry what it checks
- `notes_only` on a drafts directory - and then the line names the reason
instead of saying "no rules", which on a drafts directory would read as a
rules-file bug: `check notes_only: skipped (a drafts directory carries no
speaker notes)`.

**The `assets` manifest.** `[assets] brand = "relay"` checks
`brands/<name>/assets.toml` against the brand directory: every file that is
**not** in the text allowlist (`.py .md .toml .css .txt .json .html`) and not
in `__pycache__` must be listed, with a matching sha256 and a non-empty
provenance string, and every listed path must still exist. The rule is
"everything except a short text allowlist" rather than "every known binary
extension", because an extension-keyed check lets whoever adds the file
choose its blind spot. Malformed entries and duplicate paths are refused
outright: a duplicate would let a second, well-provenanced block mask a first
block with none.

Generate the manifest with:

```
python scripts/lint_deck.py manifest --brand relay
```

which prints one `[[asset]]` block per file with its hash and an empty
`provenance = ""` for a human to fill in. It never writes the file, and it
never invents a provenance.

**`assets.toml` and `fonts.toml` are different manifests.** `assets.toml`
says where a committed binary came from and is regenerated wholesale from
what is on disk, which is why a `[[font]]` block written into it would be
dropped on the next regeneration. `brands/<name>/fonts.toml` sits next to it
and says what `scripts/fetch_fonts.py` should fetch, from which URL, against
which sha256 and under which licence. A fetched face appears in both: the
script writes the file, a human records it. `tests/test_fetch_fonts.py`
holds `brands/relay`'s six faces to their pins without touching the
network.

**What lint cannot judge: a picture's provenance.** No lint can look at a PNG
and know whose mark it is. What it can do is refuse any file nobody has
accounted for, which is what the manifest is - design decision D4 enforced as
bookkeeping rather than as an image judgement. `examples/` is not covered by
this check today; it holds no non-text files, and that half of the
no-third-party-marks constraint stays a review matter.

Pinned by `tests/test_lint_deck.py` and the `walkthrough lint` gate step.
Needs Python only.

## The HTML deck

When the spec's `**Output:**` line says `html`, the drafts are the deck and
there is no package to check. Two of the three kinds of check still apply,
and they apply to the same artifacts a PPTX deck's do - the text, and the
pixels.

```
python scripts/build_html_deck.py --drafts examples/ai-horizon/drafts --out out/ai-horizon/html --expect-slides 10
python scripts/lint_deck.py --deck examples/ai-horizon/drafts --rules examples/ai-horizon/lint.toml --expect-checks 7
python scripts/capture_drafts.py --drafts examples/ai-horizon/drafts --out out/ai-horizon/png_html --root . --expect 10
python scripts/compose_qa.py band --png-dir out/ai-horizon/png_html --box 0,836,1600,900 --expect 10 --out out/ai-horizon/qa_html/band.png
```

`examples/ai-horizon/run_html.ps1` is those four steps and their assertions,
and the gate runs it.

**Lint on a drafts directory.** `--deck` accepts a directory holding
`sNN-*.html`. Text is harvested from the markup with `html.parser`, one
"slide" per file in slide order - numeric, so `s10` is not read before `s02`
- with `<title>`, `<style>` and comments left out, because none of them is
on the slide. Every block element ends a line, so a kicker written as its
own `<div>` stays a paragraph and the `[kickers]` pattern still has the line
boundary it relies on.

Every check runs except `notes_only`, which is **skipped with its reason**
rather than with "no rules":

```
check notes_only: skipped (a drafts directory carries no speaker notes)
LINT PASSED ran=7 skipped=1
```

`assets` is unchanged: it checks the brand package, not the deck. Lower
`--expect-checks` by one against the PPTX run of the same rules file - the
ai-horizon deck lints at 8 as a package and 7 as drafts, from one
`lint.toml`.

**One exception to reading the markup literally: `[kickers]` folds case.** A
kicker is a label, and a design system sets its labels uppercase in CSS, so
`<div class="kicker">01. How to read this</div>` reads `01. HOW TO READ
THIS` on the slide and is written uppercase into the PPTX. The markup
carries the source case, so on a drafts directory the pattern and the
allowlist are matched against an uppercased copy. `required` and `exact` do
**not** fold: they compare strings the spec fixed, and a draft that writes
its boilerplate in the wrong case says the wrong thing. Resolving
`text-transform` properly would mean implementing selector matching and
cascade order in the linter, and getting that subtly wrong would silently
change what `[exact]` compares. Pinned by
`tests/test_lint_deck.py::test_a_draft_kicker_uppercased_by_css_is_still_matched`
and `tests/test_lint_deck.py::test_required_and_exact_do_not_fold_case_on_drafts`.

**Composition on captures.** `scripts/capture_drafts.py` writes one
`sNN.png` per draft at 1600x900 - the same filenames and the same size
`export_png.ps1` writes - so every crop box in this file, and the 1.25
factor they are derived with, is unchanged. The drafts are **served** over a
loopback server rooted at `--root` rather than opened as `file://` URLs, for
the reason `references/02-html-stage.md` gives about `@import`.

**The capture is required, and it used to be optional.** Until 2026-09-10
this script printed `CAPTURE SKIPPED: Playwright is not importable` and
exited 0, so the gate's HTML step reported SKIPPED and stayed green - and a
deck could reach a stage page with ten drafts nobody had looked at. An agent
that cannot screenshot its drafts cannot judge them. So the script now tries
Python Playwright, then every Chromium-family binary on the machine
(`references/02-html-stage.md#capturing` has the search order, the 60-second
per-capture timeout and the `DECKWRIGHT_BROWSER` override), and only then
fails - with `CAPTURE UNAVAILABLE`, three remedies and the diagnostics for
every route it tried. Each PNG is checked against `1280x720 x scale` before
it counts. Pinned by `tests/test_capture_drafts.py`, in particular
`test_no_route_at_all_fails_loudly_and_says_what_to_do` and
`test_a_capture_of_the_wrong_size_is_refused`; `scripts/doctor.py` reports
the same requirement before a deck is started, pinned by
`tests/test_doctor.py`.

**The stage page, and what is asserted about it.**
`scripts/build_html_deck.py` writes `<out>/index.html`: every draft embedded
in order at 1280x720, one visible at a time, arrow keys and Home/End and
click to navigate, a `N / M` counter, and a print stylesheet that puts one
slide on one 13.333in x 7.5in page - 1280x720 CSS px at 96dpi, PowerPoint's
own 16:9 sheet - so "print to PDF" in the browser yields a PDF deck. The
drafts are embedded rather than iframed because browsers print an iframe as
one clipped box or not at all.

**No external network resource reaches the page.** Every stylesheet and
image href is rewritten to a path relative to the output directory, and an
absolute `http://`, `https://` or protocol-relative URL is refused with a
sentence saying why - a stage page that fetches a font from a CDN renders
differently on the client's machine and not at all offline. `--expect-slides
N` is exact, the same rule the rest of this file keeps: a glob that matched
four drafts of ten builds a four-slide deck that looks exactly like a
successful build. Pinned by `tests/test_build_html_deck.py`.

Needs Python only. No Windows, no PowerPoint, no COM.

## Native shapes, not images

```
python scripts/assert_native.py out/walk/deck.pptx --autoshapes 1 --max-pictures 0 --no-dangling
```

Asserts what the built package actually contains: an exact auto-shape count,
a picture ceiling (`--max-pictures`) and floor (`--min-pictures`, because a
ceiling alone still passes with the picture deleted), an optional freeform
floor, an exact embedded-font part count (`--expect-fonts`), and
`--no-dangling` to reject dangling animation targets. It also fails if any
text frame anywhere in the slide parts carries autofit, because the builder
measures and PowerPoint is never asked to fit text. The doctrine behind all
of it is in `references/03-pptx-stage.md`; this is only the assertion.

Needs Python only.

## Text dump and diff

```
python scripts/dump_text.py --deck DECK.pptx --out work/v3_text.txt
python scripts/diff_package.py OLD.pptx NEW.pptx
```

`dump_text.py` writes one line per paragraph, four tab-separated fields:

```
position[ (hidden)]  <TAB>  shape_id  <TAB>  paragraph_index  <TAB>  text
```

Tabs and newlines inside the text are replaced by spaces, so every paragraph
is exactly one line and the file diffs cleanly. Shapes are walked through
groups, so grouped text is in the dump. It refuses to write over its own
input.

`diff_package.py` compares two packages part by part, which catches what a
text dump cannot: a part added, removed or changed in ways that never reach a
paragraph.

**The procedure, and it is a procedure, not a tool:** dump the author's
current file *before* doing anything; diff that dump against the last one you
took; read the diff; only then build. There is no undo for regenerating over
someone's manual edits, and nothing else in this repository will notice them.
Catalogue item 22, pinned by
`tests/test_new_version.py::test_dump_text_round_trips_and_diff_reports_the_change`
and by the `walkthrough text dump` gate step.

Needs Python only.

## Without Windows

**Lost:** the doubled COM open, so nothing proves the package opens; the PNG
export, and with it every composition check, since `compose_qa.py`'s input is
the export; and COM's own hidden-slide report from `check_pptx.ps1`'s
`hidden=` field.

**Still runs:** `scripts/lint_deck.py` in full, `scripts/assert_native.py`,
`scripts/dump_text.py` and `scripts/diff_package.py`, `dangling_refs` from
`deck_kit.merge`, and `notes.read_notes` - so the text, the shape inventory,
the notes and the relationship graph are all still checkable. The hidden flag
is still readable from the package XML (`show="0"` on `<p:sld>`), which is
what `dump_text.py` and `pagenums.visible_numbers` use; what is lost is
PowerPoint's independent confirmation of it.

This matches the platform matrix in `references/00-pipeline.md`. The build
itself is fully portable: only QA is not.

**An `Output: html` deck loses none of it**, because none of it applies:
there is no package to open, no COM export, and the composition input is
